# دورة حياة النظام الكاملة (E2E System Pipeline)
**نظام إدارة النقل المدرسي SaaS**

## المرحلة 1: التسجيل وتهيئة المنصة (Platform Provisioning)
1. **الاشتراك:** تقوم المدرسة بطلب اشتراك عبر موقع المنصة.
2. **الاعتماد:** يقوم مالك المنصة (Platform Admin) باعتماد الطلب، واختيار الباقة (Plan)، وتحديد حد الطلاب/الحافلات.
3. **التهيئة (Provisioning):** النظام ينشئ حساب الـ `School` و `SchoolUser` لمدير المدرسة (Super Admin).
4. **العزل (Tenant Isolation):** يتم إنشاء معرّف `schoolId` خاص بالمدرسة يُستخدم في كل الجداول لعزل البيانات.

## المرحلة 2: إعداد المدرسة (School Setup)
1. يضيف مدير النقل المدرسي الحافلات (Buses) والمشرفين (Supervisors) والسائقين (Drivers - كحسابات إدارية فقط).
2. يُسجل الطلاب (Students) وبيانات أولياء أمورهم (Guardians).
3. تُضاف عناوين سكن الطلاب (Student Locations) كنقاط جغرافية (Lat/Lon).

## المرحلة 3: التخطيط الذكي للمسارات (Route Planning & Proximity)
1. **تقارب الطلاب:** يقوم نظام Backend (الـ Proximity Engine) بتصفية وتجميع الطلاب جغرافياً باستخدام خوارزمية (Haversine Formula). لا يوجد تتبع حي، بل يعتمد النظام على الإحداثيات الثابتة للمنزل أو نقطة التجمع.
2. **إنشاء المسارات:** تُربط الحافلة بالمسار، وتُضاف نقاط التوقف (Stops).
3. **توزيع الطلاب:** يتم تعيين الطلاب للمسار بناءً على مسافة قريبة من النقاط (Stops).

## المرحلة 4: التنفيذ والرحلات (Trip Execution)
1. **بدء الرحلة:** يبدأ المشرف (Supervisor) الرحلة باستخدام التطبيق (Flutter). 
2. **تحضير الطلاب:** المشرف يستخدم التطبيق لتأكيد صعود الطلاب أو غيابهم.
3. **التحديث الحي للحالة التشغيلية:** تُرسل الأحداث التشغيلية (BOARDING, NO_SHOW, ARRIVED_SCHOOL, DROPPED_OFF) إلى الخادم عبر (Sockets) لتمكين أولياء الأمور من معرفة حالة ابنه. لا يوجد تتبع حي ولا يتم إرسال موقع المشرف أو الحافلة.
4. **نهاية الرحلة:** عند الوصول للمدرسة أو انتهاء التوصيل، تكتمل الرحلة وتُسجل التقارير.
